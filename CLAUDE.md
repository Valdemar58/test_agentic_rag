# CLAUDE.md — правила работы над проектом

## Правило сессии

В начале каждой сессии прочитай `TZ_agentic_rag_mvp.md` и `PLAN.md`. Продолжай с первого незавершённого пункта текущего этапа. `PLAN.md` — единственный источник правды о ходе работ: обновляй его после каждой задачи, не в конце этапа скопом. ТЗ — единственный источник требований; его не переписывать и не расширять.

## Порядок выполнения

- Строго один этап за раз, внутри этапа — одна задача за раз.
- Задача `[x]` только когда: код написан, `uv run check` проходит, AC задачи выполнены, способ проверки записан в `PLAN.md`.
- В конце каждого этапа — обязательная остановка: отчёт (что сделано, результаты проверок, что можно продемонстрировать), чек-лист этапа, напоминание о неподтверждённых допущениях, вопросы к следующему этапу. Следующий этап — только после явного подтверждения заказчика.
- В конце каждого ответа — краткий срез чек-листа текущего этапа: ✅ сделано / 🔄 в работе / ⬜ осталось.
- Если требование ТЗ невыполнимо или противоречиво — остановиться, описать проблему, предложить варианты. Решение принимает заказчик. Молча отступать от ТЗ запрещено.
- Метрики M1–M8 не помечать достигнутыми на синтетических данных — только на реальном экспортированном корпусе.
- Неблокирующие вопросы задавать перед этапом, которого они касаются; пока ответа нет — допущение в `PLAN.md` с пометкой [ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ].

## Запреты

Из раздела 7 ТЗ (реализация запрещена без согласования): поиск в интернете; гибрид LLM+SLM; память о пользователе и логика поверх 👍/👎; исполнение кода агентом; самосоздание скиллов; генерация графиков; авторизация и enforcement ACL (но поле `acl_groups` в схеме индекса обязательно); подключение к живой СЭД из dev; семантический чанкинг; многопользовательский режим. Связи между документами — только из карточек СЭД.

Правила репозитория:
- Код SDK Тессы и сервиса карточек НЕ копировать в репозиторий (ни целиком, ни файлами). Пути только через `TESSA_SDK_PATH` и `CARD_SERVICE_PATH`. Схемы карточек импортируются как внешний пакет через `src/contracts/`.
- Сырые SQL-строки и `text()` запрещены. Только ORM. Схема — только Alembic-миграциями.
- `requirements.txt` не использовать. Без магических констант: всё в `configs/app.yaml`.
- Никаких внешних API в рантайме. Веса моделей — pinned revisions, загрузка отдельным шагом, рантайм офлайн.
- Ручное составление карточек JSON запрещено: источник правды — сериализованные экспорт-скриптом реальные карточки; до экспорта — фикстуры, сгенерированные из pydantic-схем, с пометкой «данные синтетические».

## Команды проверок (NFR-6)

```
uv run ruff check
uv run ruff format --check
uv run mypy
uv run pytest
make check          # всё вместе (Linux)
uv run check        # то же, кроссплатформенно (на Windows нет make)
```

Все четыре команды обязаны проходить без ошибок перед пометкой любой задачи `[x]`. Тесты, зависящие от внешних путей, GPU или живых сервисов, скипаются с понятным сообщением при их отсутствии, а не падают (маркеры `contract`, `gpu`, `integration`).

## Бюджет VRAM — 12 GB, обязателен на любой карте

- Рантайм: только `vllm-qwen` (Qwen3-8B AWQ ~6.5 GB + KV-cache). Эмбеддинги и reranker — на CPU.
- Инжест: только `vllm-dots` (dots.mocr монопольно); эмбеддинги на GPU после выгрузки VLM.
- Профили `runtime` и `ingest` взаимоисключены скриптом оркестрации, а не договорённостью.
- Разработка идёт на RTX 5080 16 GB, приёмка на RTX 3080 12 GB: лимиты `gpu-memory-utilization`/`max-model-len` в конфиге рассчитываются под 12 GB.

## Конвенции кода

- Docstrings, комментарии, `Field(description=...)`, промпты и UI — на русском. Без докстрингов на тривиальный код.
- Зеркалим конвенции сервиса заказчика: ruff `E,F,I,UP,B`, line-length 110; mypy strict + pydantic plugin; async SQLAlchemy 2.0 с naming convention; Alembic-ревизии `0001_slug.py`.
- Тесты: `tests/unit`, `tests/contract`, `tests/integration`, `tests/e2e`; фейки вместо `unittest.mock` там, где есть протокол.
- Коммиты атомарные, по одной задаче; после каждого этапа — работающее состояние.

## Внешние пути

- `TESSA_SDK_PATH` — папка SDK Тессы (пакет `tessa_client`, `src/tessa_client`).
- `CARD_SERVICE_PATH` — папка FastAPI-сервиса карточек (`src/robot_skills`; контракт — `robot_skills.core.cards.schemas`).
- Значения задаются в `.env` (см. `.env.example`), в CI могут отсутствовать.
