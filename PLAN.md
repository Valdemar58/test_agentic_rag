## Факты о внешнем коде (краткая выжимка; полная — `docs/tessa_analysis.md`, этап 1.3)

- SDK `tessa_client`: sync, логин/пароль; `cards.get(id)` → `Card` с секциями-словарями; `get_file_content(card_id, file_row_id, version_row_id)` → bytes; `views.get_data(alias, params)` — единственный поиск/справочники; `Card.model_dump()` не lossless; `print(payload)` на каждый запрос в `resources/base.py`.
- Связи: `OutgoingRefDocs` (`DocID, DocDescription, DocTypeName, Order, RefTypeID, RefTypeName, RefTypeReverseName`), `IncomingRefDocs` (`DocID, DocDescription`). Справочник типов — view `RefType`.
- Статусы: `DocumentCommonInfo.StatusID` (справочник заказчика), `StateID/StateName` (`$KrStates_Doc_*`, маршрут), `KrApprovalCommonInfoVirtual.StateName` (согласование).
- Сервис карточек: контракт `robot_skills.core.cards.schemas.CardData`; маршруты `POST /core/cards/get`, `POST /core/cards/get-file-content`, `POST /core/cards/get-file-versions`, `POST /core/views/{alias}/get-data`, `GET /core/card-types`, `GET /health`; HTTP Basic; Python ≥3.13; ruff `E,F,I,UP,B` line 110; mypy strict + pydantic plugin; async SQLAlchemy; Alembic `0001_slug.py`.
- Среда: Windows 11, Docker Desktop (WSL2, nvidia runtime), RTX 5080 16 GB, 34 GB RAM (VM 16 GB), uv 0.12.1, без `make`.
- Пример реальной карточки заказчика `card_response_example.json` (приказ №144, `OrderMKC`, отменён приказом №173): `DocumentCommonInfo` содержит `FullNumber`, `DocDate`, `Subject`, `DocTypeTitle`, `DepartmentID/DepartmentName`, `AuthorName`, `RegistratorName`, `SignedByName`, `StatusID/StatusNameStatus`, `StateID/StateName`, `Comment` («Отменен приказом от 27.08.2026 № 173.»), `NumberSheets`, `NumberSheetsApplication`, `SecondaryFullNumber` (номер проекта). `OutgoingRefDocs` → приказ №109 с типом «в отмену»/«отменено»; `IncomingRefDocs` → приказ №173 (без типа).
